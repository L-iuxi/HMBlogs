# Agent的四种记忆类型
Agent有四种记忆类型，按照最短到最持久来分类。
## 感知记忆
最短暂的一层，一般指这次调用的原始输入。用户发来的消息，上传的截图，传入的文档，他的生命周期只有一次调用，处理完就消失，不会主动保留。

## 短期记忆
context window(上下文窗口)里面的message列表，维护着当前任务运行过程中的完整状态，很多文章中描述这种记忆为：草稿纸。任务对话关闭，这段记忆就消失了，上下文窗口有Token上下，可以压缩，handoff，摘要等方式压缩上下文

## 长期记忆
长期记忆是跨任务保留的信息，存在外部数据库，比如向量数据库，关系数据库或者KV存储，任务结束了，信息不会消失。长期记忆的关键技术是向量数据库，支持语义检索。我们不需要知道存的时候用了什么关键词，只要意思相近，就可以检索到相关内容，这比精准匹配灵活的多。

> 比如说存的是「用户不喜欢冗长的注释」
> 用「代码风格偏好」去查询也可以查询到

长期记忆并不是固定的，可以分成三种子类型
- 「情节记忆」，存的是具体的事情经历，比如“上周写了一个什么模块，遇到了什么问题，最后用什么解决的”。这是一段完整的任务经历。
  这种记忆的价值在于，当Agent遇到新的类似任务的时候，可以检索出历史上的相似经历，参考上次是怎么解决的，避免重复踩坑/

- 「语义记忆」，存的是从多次经历中提炼出来的通用知识和规律，比如同一种情况遇到好几次之后，Agent总结出解决这种问题的规律。相比较于某一条事件的记录，这是总结出来的抽象知识，更容易命中

- 「程序记忆」，存的是怎么做某某件事的操作流程，这是一套直接可以复用的流程，再处理重复性工作的时候特别有用

## 实体记忆
比长期记忆更精炼，存成结构化偏好。信息密度高，查询快

# Agent记忆的优化方法
## 知识图谱
向量数据库做语义检索，本质上是一条一条的取记忆，每条记忆是独立的，没有关联，但很多时候，信息之间的关系和信息本身一样重要。
知识图谱通过「实体->关系->实体」的三元关系来存储信息，可以形成网状的知识结构。查询的时候可以沿着关系链条做**多跳推理**。

## 记忆整合
记忆整合是对长期记忆里面大量的碎片化信息做整理，防止检索的时候淹没在无用信息里面。包含几个关键环节：
- 去重：语义相近的多条记忆合并成一个更完整的版本
- 冲突消除：两条记忆冲突的时候，标记旧的未过期，保留新的那条
- 抽象提炼：把情节记忆转化为语义记忆

## 记忆压缩
记忆压缩是对context的内容进行压缩，常见的方法有
- 滑动窗口：超出记录长度就删除最开始的记录。这样的缺点是硬截断。
- 摘要压缩：不直接丢弃即将超出窗口的历史，而是先让LLM总结成一段精华摘要。代价是摘要会丢失细节，LLM会依照自己判断的「重要性」来决定保留什么，省略什么。
- 重要性过滤：相比较前两种按照时间筛选，重要性过滤是一种按照重要性过老的方法，给每条对话打一个重要值分数，低于阈值的淘汰，高分的保留
- 结构化抽取：提取对话中的信息存成结构化字段，后续注入prompt的时候直接用这些字段，这样信息密度更高
